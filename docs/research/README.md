# Summary

- **OFF API:** v3 is current; product reads are limited to 15 req/min, search to 10 req/min, and search is v2-only [S4][S45]. Browsers should send `X-User-Agent`, which the OFF CORS config allows [S89].
- **Eco fields depend on the API version:** below v3.1 the API maps `environmental_score` back to `ecoscore`, so request v3.1 or later to get `environmental_score_*` [S9].

- **Nutri-Score 2023:** general foods A≤0 / B 1–2 / C 3–10 / D 11–18 / E≥19; fats, oils, nuts and seeds A≤−6 / B −5–2; beverages: water only A, then B≤2 / C 3–6 / D 7–9 / E≥10 [S35][S10].

- **FDA:** DVs are saturated fat 20 g, sodium 2300 mg and added sugars 50 g [S98]. The proposed Nutrition Info box uses Low ≤5% DV / Med 6–19% / High ≥20% and is still not final in late 2026 [S1][S34]. The "healthy" compliance date is 25 February 2028 [S81].

# Data sources and scoring for a client-side food health scanner PWA (USA, France, Germany, worldwide — late 2026)

## 1. Open Food Facts (OFF) API

### Versions and endpoints

OFF documents v3 (latest v3.6) as the current API, recommended for all new integrations; v2 is deprecated but still supported, and v1/v0 are legacy [S4].

The OFF cheatsheet shows product reads with a `fields` parameter to limit the response, for example `/api/v2/product/3017620422003.json?fields=product_name,brands,nutriments` [S45].

Structured search is only available through `/api/v2/search`; the cheatsheet states that `/api/v3/search` is not yet implemented [S45].

v3 also exposes taxonomy suggestions, for example `/api/v3/taxonomy_suggestions?tagtype=categories&string=organic` [S45].

To show how a Nutri-Score was computed, the OFF tutorial recommends requesting extra fields such as `nutriscore_data` and `nutriments` [S16].

### Rate limits

OFF enforces 15 req/min per IP for all product reads (`GET /api/v*/product` or the product page) and 10 req/min per IP for all search queries, and warns that search-as-you-type would be blocked very quickly [S4].

When requests come directly from users (for example a mobile app), the rate limits apply per user [S4].

OFF also applies global rate limits irrespective of IP and answers HTTP 503 when they are exceeded [S4].

Exceeding the limits can lead to an IP ban, which OFF says can be reverted on request [S4].

For more than a few hundred products, OFF asks reusers to download the CSV or JSONL export instead of calling the API [S4].

A third-party project corrected a documented "100 per minute" figure to the published limit of 15 product reads per minute [S80].

An earlier OFF server issue on a rate-limit policy first proposed 30 req/min on product page and product API calls [S31].

### User-Agent, X-User-Agent and CORS

OFF asks every client to send a custom User-Agent of the form `AppName/Version (ContactEmail)` [S4].

The OFF forum summary states that a custom User-Agent must always be used when calling the API [S62].

The official Python SDK takes the application's user agent as a constructor argument [S105].

Browsers do not let JavaScript change the standard User-Agent header, so the Open Prices project adopted `X-User-Agent` as the only way for a web app to identify itself, aligning with the OFF API [S89].

That Open Prices pull request quotes the OFF nginx CORS directive as `Access-Control-Allow-Headers 'DNT,User-Agent,X-User-Agent,X-Requested-With,...'` [S89].

An independent project checked on 2026-10-17 that the anonymous product API returned 200 with CORS, while `/cgi/search.pl` and `/api/v2/search` returned 503 for anonymous users [S69].

A live probe run during this research (2026-10-29) on `/api/v3/product/3017624010701.json` returned HTTP 200 with `access-control-allow-origin: *` and an allow-headers list containing `X-User-Agent`, and the OPTIONS preflight returned 204 with the same headers [M].

### Nutri-Score, NOVA and environmental fields

A reimplementation of the 2023 Nutri-Score for USDA products validates its output against OFF and states that it mirrors OFF's `Nutriscore.pm` logic [S115].

The live probe showed `nutriscore_version: "2023"`, a `nutriscore` object keyed by `2021` and `2023`, and a `nutriscore_data` object with components, negative and positive points, grade, and flags such as `is_beverage`, `is_water`, `is_cheese`, `is_red_meat_product` and `is_fat_oil_nuts_seeds` [M].

OFF renamed its internal `ecoscore` fields to `environmental_score` in server PR #11142 [S9].

That PR keeps compatibility for older clients: its commit log includes "rename environmental_score to ecoscore for version < 3.1", and it copies `environmental_score_tags` to `ecoscore_tags` [S9].

The public name changed too: the Green-Score has been the new name of the Eco-Score since the end of 2024 [S75].

A later server PR shows the old name still in use internally, with `/facets/environmental-score` resolving to `ecoscore` [S26].

One client app reads the Green-Score as A+ to F and prefers the renamed `environmental_score_grade` field [S21].

In the live probe, `/api/v2/` and `/api/v3/` returned `ecoscore_grade`/`ecoscore_score` and no `environmental_score_*` keys, while `/api/v3.1/` and `/api/v3.6/` returned `environmental_score_grade`/`environmental_score_score` and no `ecoscore_*` keys, both with the same values (grade d, score 35) [M].

### Additives taxonomy and EFSA overexposure risk

OFF's additives taxonomy carries the properties `efsa_evaluation_date`, `efsa_evaluation_exposure_mean_greater_than_adi`, `efsa_evaluation_exposure_95th_greater_than_adi`, `efsa_evaluation_overexposure_risk` and `efsa_evaluation_url` [S50].

OFF stopped its own 2012 risk ratings because a factual and neutral assessment was hard to make, and it now analyzes EFSA evaluation reports for overexposure risks instead [S85].

The original proposal was to extract structured data from EFSA evaluations on the risk of overexposure for given population groups [S56].

In the OFF additives taxonomy, `efsa_evaluation_overexposure_risk` is set to `en:high` for E250 (sodium nitrite), E251 and E252 (nitrates), E338 (phosphoric acid), E407 (carrageenan) and E621 (sodium glutamate), among others [S50].

The same taxonomy marks E960 (steviol glycosides) as `en:moderate`, with the 95th-percentile exposure above the ADI for toddlers [S50].

It marks E951 (aspartame) as `en:no`, with an ADI of 40 [S50].

The taxonomy's E171 (titanium dioxide) entry still cites the 2016 EFSA re-evaluation and carries no overexposure-risk value [S50].

The taxonomy's E249 (potassium nitrite) entry carries no EFSA evaluation properties at all, unlike E250 [S50].

The taxonomy endpoint `/api/v2/taxonomy?tagtype=additives&tags=en:e250,...` returned these properties live, so a client can resolve `additives_tags` to risk levels without a bulk download [M].

## 2. Nutri-Score 2023 updated algorithm

### Grade thresholds

The Scientific Committee found that the updated algorithm needed a change to the A/B threshold only, up by one point [S35].

For general foods (including red meat products and cheese) the recommended final classes are A = min to 0, B = 1 to 2, C = 3 to 10, D = 11 to 18, E = 19 to max [S35].

For the fats, oils, nuts and seeds category the final classes are A = min to −6, B = −5 to 2, C = 3 to 10, D = 11 to 18, E = 19 to max [S35].

The committee's blog summary describes the same general-food change as moving the A/B threshold to 0/1 from −1/0 [S90].

For beverages, water is the only beverage in class A, and the recommended thresholds are B = min to 2, C = 3 to 6, D = 7 to 9, E = 10 to max [S10].

The beverage addendum confirms that water is maintained as the only beverage in class A [S15].

A study of 3432 Spanish beverages (Nutri-Score original vs updated) restates the updated beverage cut-offs as B up to 2, C 3 to 6, D 7 to 9 and E 10 or more [S116].

A technical reference reproduced from the Santé publique France workbook gives the score formula for general foods as `N − P` when N < 11, else `N − FVL − Fibre`, with red meat following the same rule and protein capped at 2 [S6].

That reference also states that plain water is graded A through a dedicated water flag and every other beverage is graded B to E [S6].

The beverage update adds a non-nutritive sweetener component worth 4 unfavourable points and removes the protein cap threshold for beverages [S10].

The solid-food update raises the maximum sugars points to 15 and replaces sodium with salt scored up to 20 points [S90].

### Status in Germany

The updated algorithm has applied in Germany since 2024, with a two-year transition for products already labelled; since 1 January 2026 only the updated algorithm may be used, with a sell-off allowance for products on sale before that date [S96].

The German ministry (BMLEH) states that the transition still runs in Luxembourg until March 2026 and in France until March 2027 [S96].

Foodwatch found that 33 manufacturers previously registered for Nutri-Score in Germany withdrew it from all or part of their ranges, including PepsiCo, Danone and Alpro [S52].

The updated algorithm reclassifies certain milk-based and plant-based drinks as beverages rather than foods, which lowered many ratings [S52].

PepsiCo, Danone and Alpro are among the manufacturers stepping back from the voluntary label [S86].

Nutri-Score remains a voluntary nutrition label in Germany [S60].

### Status in France

The French ministers signed the decree (arrêté) for the updated algorithm on 14 March 2025 [S78].

Companies that already use Nutri-Score have 24 months from 15 March 2025 to update their labels [S83].

The Santé publique France Q&A states that the Nutri-Score of products placed on the market after 31 December 2023 must in principle be based on the updated algorithm, subject to each country's regulatory procedure [S30].

As of 2026, Nutri-Score in France remains a voluntary, government-recommended system rather than a legal obligation [S71].

In November 2025 the National Assembly voted amendments to make Nutri-Score mandatory, with exemptions for some quality-labelled products such as PDOs [S24].

## 3. NOVA classification

NOVA was introduced in 2009 by the Brazilian epidemiologist Carlos A. Monteiro and sorts foods into four groups by the extent and purpose of their processing [S17].

OFF lists the four groups as unprocessed or minimally processed foods, processed culinary ingredients, processed foods, and ultra-processed food and drink products [S22].

OFF's NOVA page describes ultra-processed foods as formulations made mostly or entirely from substances derived from foods and additives, with little if any intact Group 1 food [S22].

Additive classes found only in ultra-processed products include colours, flavour enhancers, non-sugar sweeteners, emulsifiers, sequestrants and humectants [S22].

In OFF's code, `compute_nova_group()` collects markers, which can be additive tags (for example `additives/en:e440`) or ingredient tags (for example `ingredients/en:gelling-agent`) listed in `nova_groups_tags` in `Config_off.pm` [S8].

A server fix stops an ingredient that is also an additive from being counted as two NOVA markers; the NOVA group doesn't change, only the list and number of markers [S32].

In a test of NOVA assignments by food and nutrition specialists, Cramér's V was only 0.58 and 0.59 for marketed and generic foods, a pronounced inconsistency [S46].

A 2026 Journal of Nutrition perspective argues that NOVA Group 4 is triggered by the mere presence of cosmetic additives or industrial ingredients regardless of dose [S27].

A study of the updated Nutri-Score and NOVA concludes that the update reinforces coherence with NOVA, while the two systems measure distinct health dimensions [S5].

## 4. EFSA evaluations of additives of concern

### Nitrites and nitrates (E249–E252)

EFSA re-assessed sodium and potassium nitrite (E249–250) and nitrate (E251–252) in two opinions published in June 2017 [S28].

For nitrite, the Panel derived an ADI of 0.07 mg nitrite ion/kg bw per day; additive-only exposure did not exceed it for the general population, except a slight exceedance in children at the highest percentile [S39].

EFSA's 2023 opinion on N-nitrosamines concluded that the margin of exposure at the P95 is highly likely (98–100% certain) to be below 10,000 for all age groups, which raises a health concern [S20].

Commission Regulation (EU) 2023/2108 restated the 0.07 mg nitrite ion/kg bw ADI and amended the authorised uses of E249–E252 [S68].

The new maximum levels for meat and fishery products apply from 9 October 2025 [S49].

General meat products went from 150 mg/kg to 80 mg/kg added nitrite and sterilised meat products from 100 mg/kg to 55 mg/kg [S48].

### Titanium dioxide (E171)

EFSA's FAF Panel concluded in 2021 that titanium dioxide can no longer be considered safe as a food additive, because genotoxicity concerns could not be excluded [S36].

Under Regulation (EU) 2022/63, foods made under the old rules could be placed on the market until 7 August 2022 and then remain on sale until their date of minimum durability [S79].

The Commission adopted the E171 ban on 14 January 2022 [S2].

### Phosphates, glutamates, carrageenan and sweeteners

EFSA set a group ADI for phosphates of 40 mg/kg bw per day expressed as phosphorus [S61].

Estimated exposure exceeded that ADI for infants, toddlers and other children at the mean, and for infants, toddlers, children and adolescents at the 95th percentile [S61].

EFSA's press release recommends maximum levels for phosphates in food supplements, because people who take them regularly may be at risk [S97].

EFSA maintains an ADI of 40 mg/kg bw/day for aspartame and found no reason to revise it [S93].

In 2023 IARC classified aspartame as possibly carcinogenic to humans (Group 2B), while JECFA reaffirmed the 40 mg/kg ADI [S113].

## 5. US FDA rules

### Daily Values

FDA's reference table lists Daily Values of 20 g saturated fat, 2300 mg sodium and 50 g added sugars [S98].

FDA's general guide is that 5% DV or less of a nutrient per serving is low and 20% DV or more is high [S98].

### Front-of-package "Nutrition Info box" (proposed)

The proposed rule would require a Nutrition Info box on the principal display panel showing saturated fat, sodium and added sugars per serving with "Low", "Med" or "High" descriptors [S1].

FDA proposes 5% DV or less for "Low", 6% to 19% DV for "Med" and 20% DV or more for "High", based on the per-serving %DV already calculated and rounded for the Nutrition Facts label [S1].

The proposal sets compliance 3 years after the final rule's effective date for businesses with $10 million or more in annual food sales, and 4 years for smaller businesses [S1].

It also revises the "low sodium" claim to 115 mg or less per RACC [S1].

FDA extended the comment period to 15 July 2025 [S112].

FDA's regulatory agenda lists the front-of-package final rule for 2026/12 [S107].

The 2026 Unified Agenda summary says FDA intends to issue the final front-of-package rule "this winter" [S88].

An October 2026 timeline notes that the target moved from May to December 2026 and that the rule is still a proposal [S34].

In March 2026 FDA Deputy Commissioner for Human Foods Kyle Diamantas said "everything is on the table", including revising or rescinding the proposal [S92].

### "Healthy" nutrient content claim (final)

The final "healthy" rule was published with an effective date of 25 February 2025 and a compliance date of 25 February 2028 [S81].

FDA later delayed the effective date to 28 April 2025 while keeping the compliance date unchanged [S43].

The rule removes the total fat and cholesterol limits and adds an added-sugars limit [S76].

Limits are expressed as %DV per food group; for example an individual vegetable product may not exceed 2% DV added sugars, 10% DV sodium and 5% DV saturated fat [S63].

The final rule raised the sodium limit for mixed products to 15% DV per RACC and the added-sugars limit for grain products to 10% DV [S81].

FDA is still developing a separate "healthy" symbol [S102].

## 6. Barcode scanning in the browser

The Barcode Detection API is experimental, not Baseline, and available only in secure contexts (HTTPS) [S13].

The spec's format list includes `ean_13`, `ean_8`, `upc_a` and `upc_e`, and supported formats should be checked with `BarcodeDetector.getSupportedFormats()` [S114].

Caniuse shows Chrome for Android supported, desktop Chrome and Edge only partial, Firefox not supported, and Safari on macOS and iOS disabled by default [S67].

MDN's compatibility data says desktop Chrome support covers ChromeOS and macOS only [S73].

WebKit bug 281848 reports that the Shape Detection API stopped working on iOS 18 even with the feature flag enabled [S37].

Every iOS browser runs on WebKit, so a web app relying on BarcodeDetector silently fails on iPhones and iPads [S19].

A blog post claims Chrome 134 shipped BarcodeDetector by default and that it is available on 94% of Chrome installs [S25].

> [model-hint] That claim conflicts with the caniuse and MDN compatibility data above, which still show desktop Chrome as partial.

The `barcode-detector` package is a Barcode Detection API ponyfill/polyfill using ZXing-C++ WebAssembly and can be imported from `barcode-detector/ponyfill` [S3].

The ponyfill lists `ean_8`, `ean_13`, `upc_a` and `upc_e` among its supported formats [S3].

The older `@sec-ant/barcode-detector` package is deprecated and republished as `barcode-detector` [S82].

The `zxing-wasm` full build weighs about 1.46 MiB [S33].

In zxing-wasm v3 each format has a canonical name such as `EAN13` within a symbology such as `EANUPC` [S33].

barcode-detector v3.2.3 upgraded zxing-wasm and reports detection latency down about 40–48% in its 720p/1080p benchmarks [S94].

A ZBar-based WebAssembly polyfill is another fallback [S57].

## 7. Implications for the score

<!-- ultrasearch:no-numerals -->
- FDA-style traffic light: compute %DV = nutrient per serving ÷ DV × 100 with saturated fat 20 g, sodium 2300 mg and added sugars 50 g, then Low ≤ 5, Med 6–19, High ≥ 20 [S98][S1].

- Nutri-Score: read `nutriscore_data` when OFF provides it, and otherwise classify with the general, fats/oils/nuts/seeds or beverage thresholds above [S35][S10].

- Additives: map `additives_tags` to `efsa_evaluation_overexposure_risk` (high / moderate / no) from the OFF taxonomy [S50].

- Request the API at v3.1 or later, read `environmental_score_*`, and fall back to `ecoscore_*` for older responses [S9].

## 8. Open questions and contradictions

- **ecoscore vs environmental_score.** The brief assumed that `ecoscore_*` fields are still served while `environmental_score_*` fields are empty. That is wrong as stated. Which name you get depends on the API version you request: v2/v3 return `ecoscore_*`, and v3.1 or later return `environmental_score_*` [S9].

- The other three assumptions hold: CORS `*`, the 15 req/min product limit and acceptance of `X-User-Agent` [S4][S89][S69].

> [model-hint] The general-food A/B threshold is stated as "-1/0" in the executive summary of the Scientific Committee report, while its final table (min to 0 = A) and the committee blog say 0/1. The final table is the operative value.

> [model-hint] FoodBev says the updated algorithm "came into force on 1 January 2026" in Germany, while BMLEH says it applies since 2024 and only the transition ended then. BMLEH is the primary source.

> [model-hint] The OFF additives taxonomy lags EFSA for E171 (it cites the 2016 opinion, not the 2021 "no longer safe" conclusion) and has no EFSA data for E249, so a scanner should add a local override for those codes.

> [model-hint] The FDA front-of-package rule is not final as of late October 2026. The Low/Med/High thresholds are therefore a proposal and could change in a re-proposal.

> [model-hint] fda.gov answered the engine's fetcher with a 404 "abuse-detection" page. FDA pages were captured with a plain HTTP client and pinned with ingest --files, then relinked to their URLs.
